# 08 多用户权限与多会话设计

更新日期：2026-11-07

## 1. 结论

- 不引入 `agentscope-harness`。它面向自主编码/工作区型智能体，会带来文件系统、Shell、子智能体与 sqlite 会话持久化等无关能力；本项目的会话隔离由数据库归属字段与后端强制校验完成。
- 采用**全局 RBAC + 知识库角色**双层模型：全局角色控制系统管理与会话能力，知识库角色继续控制单个知识库的数据范围。
- 每个用户拥有多个会话，会话全局展示、绑定创建时的知识库；服务端按 `user_id` 隔离。
- 生成回答时带入同一会话最近 6 轮问答，用于理解追问与指代，不作为事实依据。

## 2. 权限模型

### 2.1 权限码

| 分组 | 权限码 | 说明 |
| --- | --- | --- |
| 用户 | `user:read` / `user:manage` | 查看 / 新增、编辑、停用、重置密码 |
| 部门 | `department:read` / `department:manage` | 查看 / 新增、编辑、启停、删除 |
| 角色 | `role:read` / `role:manage` | 查看 / 新增、编辑、删除自定义角色 |
| 会话 | `chat:use` | 使用知识库问答与会话中心 |
| 知识库 | `kb:create` | 新建知识库 |

### 2.2 内置角色

| 角色码 | 名称 | 权限 |
| --- | --- | --- |
| `ADMIN` | 平台管理员 | 全部权限 |
| `MANAGER` | 部门管理员 | `user:read`、`user:manage`、`department:read`、`role:read`、`chat:use`、`kb:create` |
| `MEMBER` | 普通成员 | `chat:use`、`kb:create` |

- `app_user.platform_admin=true` 的账号拥有全部权限，并可跨知识库访问；该标记仅平台管理员可授予。
- 内置角色不可删除、不可改角色码，权限每次启动由代码重新同步。
- 自定义角色可维护权限子集；被用户引用的角色不可删除。

### 2.3 与知识库角色的关系

- 全局权限决定“能不能进入某个功能”。
- 现有 `READER < EDITOR < ADMIN < OWNER` 决定“能操作哪个知识库”。
- 两者同时满足才放行；平台管理员直接拥有 `OWNER`。

## 3. 数据模型

### 3.1 组织与权限

- `app_user` 新增：`role_code`（可空，启动后归一）、`active`（可空，空视为启用）、`updated_at`、`last_login_at`。
- `org_department` 新增：`description`、`active`（空视为启用）。
- `sys_role`：`id`、`code`（唯一）、`name`、`description`、`permissions_json`、`builtin`、`created_at`、`updated_at`。

### 3.2 会话

- `chat_session`：`id`、`user_id`、`series_id`、`title`、`created_at`、`updated_at`。
- `chat_message`：`id`、`session_id`、`role`（`USER` / `ASSISTANT`）、`content`（CLOB）、`citations_json`、`meta_json`、`created_at`。
- 索引：`(user_id, updated_at)`、`(session_id, id)`。

## 4. 接口

统一响应 `ApiResponse`，分页 `PageResult`。

### 4.1 管理台

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/api/admin/users?keyword&deptId&active&page&size` | `user:read` |
| POST | `/api/admin/users` | `user:manage` |
| PUT | `/api/admin/users/{id}` | `user:manage` |
| PUT | `/api/admin/users/{id}/password` | `user:manage` |
| GET | `/api/admin/departments` | `department:read` |
| POST/PUT | `/api/admin/departments[/{id}]` | `department:manage` |
| PATCH | `/api/admin/departments/{id}/status` | `department:manage` |
| DELETE | `/api/admin/departments/{id}` | `department:manage` |
| GET | `/api/admin/roles` | `role:read` |
| GET | `/api/admin/permissions` | `role:read` |
| POST/PUT/DELETE | `/api/admin/roles[/{id}]` | `role:manage` |

保护规则：

- 不能停用自己、不能修改自己的角色。
- 至少保留一个启用的平台管理员。
- 部门删除前校验：无子部门、无用户、无知识库引用。
- 部门层级最多 5 级，不能移动到自身或后代节点。

### 4.2 会话中心

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/chat/sessions` | 当前用户全部会话，按更新时间倒序 |
| POST | `/api/chat/sessions` | 指定 `seriesId` 创建，默认标题“新会话” |
| PUT | `/api/chat/sessions/{id}` | 重命名 |
| DELETE | `/api/chat/sessions/{id}` | 级联删除消息 |
| GET | `/api/chat/sessions/{id}/messages` | 只读本人会话 |
| POST | `/api/chat/sessions/{id}/messages` | 发送问题，返回用户消息与助手消息 |

隔离规则：

- 用户 ID 一律取自 Token 上下文，绝不接受请求体或路径传入。
- 会话不存在与越权统一返回 `404 会话不存在或无权访问`，避免枚举。
- 创建会话与发送消息时重新校验知识库可读权限；权限被回收后不能继续提问。
- 不提供管理员读取他人会话内容的接口。

## 5. 检索与历史上下文

- 检索仍只使用当前问题召回片段，历史不参与 ES 打分。
- 生成提示词包含：最近 6 轮问答（每条截断）、资料片段、当前问题；明确历史仅用于理解指代。
- 回答落库时保存引用列表与检索元数据（引擎、模型、耗时、候选数）。
- 无匹配时落库固定提示；生成模型不可用时落库降级说明并保留引用。
- 首条用户消息自动生成标题（截取 24 字），后续不再自动改名。

## 6. 前端

- 登录与 `me` 返回 `roleCode`、`roleName`、`permissions`、`active`；前端据此显示导航与按钮。
- 新增“系统管理”导航组：用户管理、部门管理、角色权限；路由带权限元数据，无权限跳回知识库列表。
- 聊天页改为左右布局：左侧全局会话列表（标题、所属知识库、更新时间、消息数），右侧对话；移动端会话列表放入抽屉。
- 会话支持新建、切换、重命名、删除；切换会话同时切换知识库；发送首条消息自动命名。
- 保留现有微信式气泡、引用折叠与移动端适配。

## 7. 验收

1. 普通成员无法访问系统管理接口与页面，返回 403。
2. 部门管理员可管理用户，但不能管理角色与部门。
3. 张三看不到李四的会话，直接请求李四的会话 ID 返回 404。
4. 同一用户可创建多个会话，列表按最近活跃排序，重命名与删除生效。
5. 连续追问时，Ollama 提示词包含最近 6 轮；检索仍基于当前问题。
6. 停用账号后无法登录，已登录请求返回 401。
7. 删除被用户、知识库或子部门引用的部门被拒绝。
8. 最后一个平台管理员不能被停用或降级。

## 8. 非目标

- 不引入 `agentscope-harness` 或 AgentScope 运行时。
- 不做会话内容的管理员审计读取、消息分页、会话归档与置顶。
- 不做细粒度知识库字段级权限，知识库仍按现有成员角色控制。
