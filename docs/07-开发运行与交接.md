## 1. 本地启动

### 1.1 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17 | Maven 使用 `JAVA_HOME`，不是 PATH；若报“不支持发行版本 17”，先修正 `JAVA_HOME` |

### 1.2 后端

```bash
export JAVA_HOME="D:/tools/jdk/jdk-17.0.12"
export PATH="$JAVA_HOME/bin:$PATH"
cd backend
mvn spring-boot:run
```

- 端口：`8090`（`backend/src/main/resources/application.yml`）。不要改成 8080，本机可能被工资管理台占用。
- 健康检查：`GET http://localhost:8090/api/health`

- 上传文件目录：`backend/data/uploads/`。
- 停止后再次启动若提示数据库被占用，先结束残留的 Java 进程（Windows 可用 `netstat -ano | findstr :8090` 查 PID 后 `taskkill /PID <pid> /F`）。

### 1.5 外部依赖（Ollama / Elasticsearch）

两项外部服务都是可选的：未启动时应用不会崩溃，而是分别降级为“仅返回引用、不生成回答”和“本地 H2 检索”。

**Ollama（生成式回答）**

```bash
ollama serve
ollama pull qwen2.5:3b-instruct
```

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `KB_LLM_ENABLED` | `true` | 设为 `false` 时永不调用模型，`llmUsed=false` |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama 地址 |
| `OLLAMA_MODEL` | `qwen2.5:3b-instruct` | 需提前 `ollama pull` |
| `OLLAMA_NUM_CTX` | `8192` | 上下文窗口 |
| `OLLAMA_TEMPERATURE` | `0.1` | 证据型回答使用低温度 |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | 单次生成超时 |
| `OLLAMA_THINK` | `false` | 对支持思考的模型是否开启 think |

- 启动时通过 `/api/tags` 预检模型，日志会打印“Ollama 模型可用”或明确的修复提示。
- 生成只调用 `/api/chat`（非流式），提示词要求“仅依据给定片段、用 `[n]` 标注引用、不得编造”。
- 模型不可用、超时或返回空内容时，接口仍返回检索结果，`llmUsed=false`，`llmError` 给出可读原因。

**Elasticsearch（向量 + BM25）**

已验证版本为 **Elasticsearch 7.17.28（Windows 单节点）**；代码只使用 7.6.2 也具备的 API（`dense_vector`、`script_score`、`cosineSimilarity`、`cjk_bigram`、`_bulk`、`_delete_by_query`）。

```bash
# 在 Elasticsearch 安装目录执行（Windows 示例，按实际路径调整）
set ES_JAVA_OPTS=-Xms512m -Xmx512m
bin\elasticsearch.bat -Ecluster.name=kb-console-test -Enode.name=kb-console-test ^
  -Ediscovery.type=single-node -Expack.security.enabled=false -Expack.ml.enabled=false ^
  -Epath.data=<es-data-dir> -Epath.logs=<es-log-dir> ^
  -Ehttp.port=9200 -Etransport.port=9300 -Enetwork.host=127.0.0.1 ^
  -Ebootstrap.memory_lock=false -Eingest.geoip.downloader.enabled=false
```

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `KB_ES_ENABLED` | `true` | 设为 `false` 时直接走本地检索 |
| `ELASTICSEARCH_URL` | `http://localhost:9200` | ES 地址 |
| `ELASTICSEARCH_INDEX` | `kb_chunk` | 切片索引名 |
| `kb.elasticsearch.dimensions` | `256` | 与嵌入维度一致，修改需重建索引 |

行为约定：

- 启动时检查索引，不存在则自动创建 mapping（`content/titlePath` 使用 `cjk_bigram` 中文分析器，`vector` 为 `dense_vector`）。
- 索引为空且 `reindex-on-startup=true` 时，从 H2 回填全部 `ACTIVE` 非父级切片；日志会打印回填文档数与切片数。
- 入库/重解析会先删除该文档的旧切片再批量写入；文档软删除或知识库删除在数据库事务提交后清理 ES。
- 检索使用 `cosineSimilarity + 1.0` 计算向量分，再与 BM25 归一化分数加权融合；ES 不可用时自动回退本地 H2，响应 `retrievalEngine=LOCAL`。

**嵌入说明（重要限制）**

当前嵌入仍是本地 **256 维字符/CJK n-gram 哈希向量**，只是把向量存进了 ES，并未调用 Ollama 的嵌入接口。本机 Ollama 服务版本未提供 `/api/embed`，因此只使用了 `/api/chat`。若要切换真实嵌入模型：

1. 升级到支持 `/api/embed` 的 Ollama 版本，并拉取嵌入模型（如 `bge-m3` / `nomic-embed-text`）；
2. 修改嵌入实现与 `kb.elasticsearch.dimensions`，保持两者一致；
3. 全量重建索引，并删除或新建 `kb_chunk` 索引代际。

### 1.6 自动部署与运行（Windows）

生产部署采用“前端打进后端 jar”的单进程模式：`frontend/dist` 在 Maven 构建时复制到 jar 的 `static/`，由 Spring Boot 同时提供页面、静态资源和 `/api`，不需要 Nginx。

```bat
:: 首次部署或更新代码后
deploy\deploy.bat deploy

:: 日常运维
deploy\deploy.bat status
deploy\deploy.bat restart
deploy\deploy.bat stop
deploy\deploy.bat logs
```

`deploy` 的执行顺序：

1. 检测 JDK 17：优先使用 `-JavaHome`、`JAVA_HOME`，其次扫描常见 JDK 17/21 安装目录；同时把 `JAVA_HOME` 指向该 JDK 供 Maven 使用。
2. 前端依赖不存在时执行 `npm ci`，随后 `npm run build`。
3. 执行 `mvn -B -Pwith-frontend package`，把 `frontend/dist` 打进 `BOOT-INF/classes/static`。
4. 读取 `deploy-runtime/app.pid` 停止旧实例；若 8090 被本项目的旧进程占用，也会识别并停止。
5. 复制 jar 到 `deploy-runtime/kb-console.jar`，后台启动并写入 PID。
6. 轮询 `/api/health`，最多 90 秒；最后检查 Elasticsearch 与 Ollama 是否可达，并提示降级行为。

参数与产物：

| 参数/项 | 说明 |
| --- | --- |
| `-Port 8090` | 监听端口，页面与 API 同端口 |
| `-DataDir <目录>` | 数据目录，默认优先使用 `backend/data`，否则 `deploy-runtime/data` |
| `KB_DATA_DIR` | 数据目录环境变量，优先级低于 `-DataDir` |
| `-SkipTests` | Maven 跳过测试 |
| `-SkipBuild` | 使用现有 `deploy-runtime/kb-console.jar` 直接启动 |
| `-NoDeps` | 启动后不检查 ES/Ollama |
| `deploy-runtime/kb-console.jar` | 部署包 |
| `deploy-runtime/app.pid` | 当前进程 PID |
| `deploy-runtime/logs/app.log` | 应用日志（UTF-8） |
| `deploy-runtime/logs/console.out/.err` | 标准输出/错误 |
| `deploy-runtime/version.txt` | 构建时间与 jar 名 |

注意：

- Windows 会锁定正在运行的 jar，因此 `deploy` 先停旧实例再构建；构建失败时应用会保持停止，修复后重新执行 `deploy` 即可。
- 自动部署只负责本应用；ES 与 Ollama 仍按 1.5 节独立启动。它们不可用时应用仍能启动并降级。
- 页面路由（`/`、`/login`、`/chat`、`/series`、`/series/{id}`、`/series/create`、`/admin/users`、`/admin/departments`、`/admin/roles`）由 `SpaController` 转发到 `index.html`，刷新深链接不会 404。
- `deploy.bat` 会透传退出码，可直接用于计划任务或 CI：0 表示成功，非 0 表示构建或健康检查失败。
- 需要开机自启时，可将 `deploy\deploy.bat start` 注册为当前用户的“登录时”计划任务；不要重复注册多个任务。

## 3. 关键实现

### 3.1 鉴权与权限

- `AuthController` 登录校验 BCrypt 密码，签发无状态 HMAC-SHA256 Token（默认 24 小时）。
- `AuthInterceptor` 解析 `Authorization: Bearer <token>`，校验账号启用状态，写入 `UserContext`；`UserContext.require()` 供服务层取当前用户。
- 全局 RBAC：`sys_role` 存角色与权限 JSON，用户通过 `role_code` 关联；接口用 `@RequirePermission` 声明权限码，平台管理员视为拥有全部权限。权限码见 `Permissions`，前端仅用于导航/按钮显隐，服务端仍强制校验。
- 知识库级角色：`READER < EDITOR < ADMIN < OWNER`。
  - 个人授权（`USER`）与部门授权（`DEPT`）取并集，取最高角色。
  - 平台管理员直接视为 `OWNER`。
  - 写接口分别调用 `requireMaintain` / `requireAdmin` / `requireOwner`；前端 Tab 只是视图门禁，服务端仍强制校验。
- 当前“可访问/可维护”列表通过 `scope=accessible|maintainable` 区分。

### 3.2 配置版本

- 保存配置会生成不可变 `kb_config_version`，知识库的 `active_config_version_id` 指向新版本。
- 入库任务在创建时固化 `config_version_id`，运行中改配置不影响已排队任务。
- 保存时可选择 `rebuild.scope`：
  - `NONE`：只生成版本；
  - `FAILED`：为失败文档创建重建任务；
  - `FULL`：为全部文档创建重建任务。
- 前端设置页右侧展示版本历史，可载入历史版本参数后再另存为新版本。

### 3.3 文档入库链路

1. `POST /documents` 校验扩展名、大小、重复文件策略（`SKIP` / `OVERWRITE`），落盘并创建文档与任务。
2. `kbTaskExecutor` 异步执行 `IngestProcessor`：
   - `PARSE`：PDFBox / Apache POI / CommonMark 提取文本；
   - `CHUNK`：按配置版本选择默认、按行、父子、标题增强或自定义切分；
   - `EMBED`：本地 256 维哈希向量；
   - `INDEX`：切片写入 H2，替换该文档在 Elasticsearch 中的切片，并更新文档、知识库统计；ES 失败只记 `WARN`，不阻断入库。
3. 每一步写 `kb_task_log`，任务中心可看时间线、耗时、失败原因；`INDEX` 节点会记录“Elasticsearch 索引完成：N 个切片”或降级原因。
4. 前端文档列表在存在 `PENDING/PARSING/CHUNKING/INDEXING` 时每 3 秒轮询，任务中心在 `QUEUED/RUNNING` 时轮询。

### 3.4 检索与生成

检索分两条路径，由服务可用性自动选择：

1. **Elasticsearch 路径**（优先）：`dense_vector` 余弦相似度 + `multi_match` BM25（中文 `cjk_bigram`）双路召回，取并集后按 `vectorWeight` 加权融合，再按阈值过滤、TopK 截断。
2. **本地 H2 路径**（回退）：字符 n-gram 哈希到 256 维并归一化，关键词 BM25，同样加权融合；ES 连接失败或返回空结果时自动切换。

公共后处理：

- 精排：`0.7 * 融合分 + 0.3 * 查询词覆盖度 + 标题命中加成`，可在请求中关闭。
- 引用：返回文档、页码、标题路径、切片序号、父切片内容（父子切分时），并按 `chunkId` 回查 H2 再次校验文档/切片状态，避免 ES 中出现陈旧数据。
- 生成：`generate` 默认为 `true`。命中引用后，取前 `maxContextChunks` 条（优先父切片内容，总字符受 `maxContextChars` 限制）调用 Ollama `/api/chat`，要求严格依据片段并用 `[n]` 标注来源。
- 降级：模型不可用/超时/返回空时，引用照常返回，`answer=null`、`llmUsed=false`、`llmError` 说明原因；ES 不可用时 `retrievalEngine=LOCAL`。
- 检索测试页固定发送 `generate=false`，只看召回质量，不触发模型；聊天页发送 `generate=true`，展示生成答案与可折叠引用。
- 会话追问：聊天页发送时会把该会话最近 12 条消息（6 轮）作为历史传给 `OllamaService.generate`，仅用于理解指代；检索仍只用当前问题。

## 6. 调试与排查

- **请求追踪**：响应统一带 `traceId`，后端 `TraceIdFilter` 写入日志上下文，前端错误提示会展示后端 message。
- **入库排障**：优先看任务中心“日志”时间线，失败节点会显示 `PARSE / CHUNK / EMBED / INDEX` 与错误码；错误码定义在 `common/ErrorCodes.java`。
- **权限问题**：`GET /kb/series/{id}` 对无权限用户返回 404（避免泄露存在性），写接口返回 403 `KB_40301`。
- **前端接口 404**：确认后端在 8090，且访问的是 Vite 5173（不要直接打开 `dist/index.html`）。
- **上传失败**：检查扩展名是否在 PDF/DOCX/XLSX/XLS/MD 内、单文件 ≤ 100 MB、单批 ≤ 50 个；重复文件按 `dedupeAction` 处理。
- **中文文件名**：Windows 下用 curl 上传时路径需转 Windows 形式（如 `cygpath -w`），否则 curl 报 26。
- **H2 锁**：不要同时启动两个后端实例；异常退出后检查 8090 端口占用。
- **回答没有生成（`llmUsed=false`）**：先看 `llmError`。常见原因：Ollama 未启动（`ollama serve`）、模型未拉取（`ollama pull qwen2.5:3b-instruct`）、超时。可临时设 `KB_LLM_ENABLED=false` 只做检索。
- **`retrievalEngine=LOCAL`**：说明 ES 未连接或检索失败。检查 `curl http://localhost:9200`、`KB_ES_ENABLED`、索引是否存在；后端日志会打印 ES 不可用原因。
- **ES 中文检索无结果**：确认索引 mapping 由应用自动创建（使用 `cjk_bigram`），不要手工建一个标准分析器的 `kb_chunk`；必要时删除索引后重启后端回填。
- **ES 启动失败**：Windows 下不要使用仓库外的 Linux 版 7.6.2 目录；使用 7.17.x 的 `.bat`，并确保 9200/9300 未被占用、数据目录可写。
- **切片数与 ES 文档数不一致**：入库/重解析会替换该文档的 ES 切片；若曾手动改库，删除 `kb_chunk` 索引并重启，等待启动回填完成。
