# 知识库智能助手 · 系统管理台

> 文档状态：方案稿 v0.1（2026-11-07）
> 适用范围：知识库（系列）管理台的需求、交互、数据、接口与解析检索设计
> 关联产品：知识库智能助手（管理台 + 问答侧“新会话”）

## 1. 项目定位

面向企业部门的知识库运营台，覆盖一条知识的完整生命周期：

**创建知识库 → 选择文档类型与解析方式 → 配置切片 → 配置检索 → 授权成员 → 上传知识 → 解析/切片/索引 → 检索与引用溯源**

本方案聚焦“知识库系统管理”，并实现了按账号隔离的多会话问答中心作为下游消费示例：每个用户可以创建多个会话，会话绑定知识库并持久化历史消息。

当前仓库已包含可运行的 Spring Boot + Vue 实现：后端 `backend/`、前端 `frontend/`。检索侧接入 Elasticsearch（向量 + BM25），问答侧接入 Ollama 生成（RAG + 引用约束），两者不可用时自动降级。运行方式与交接说明见 [07-开发运行与交接](docs/07-开发运行与交接.md)。

## 2. 快速启动

```bash
# 可选：生成式回答（未启动时只返回检索引用）
ollama serve
ollama pull qwen2.5:3b-instruct

# 可选：Elasticsearch 7.17.x（未启动时回退本地 H2 检索）

# 后端（JDK 17）
export JAVA_HOME="D:/tools/jdk/jdk-17.0.12"
export PATH="$JAVA_HOME/bin:$PATH"
cd backend && mvn spring-boot:run

# 前端（另开终端）
cd frontend && npm install && npm run dev
```

- 前端：`http://127.0.0.1:5173/`
- 后端：`http://localhost:8090/api/health`
- 演示账号：`zhangsan / lisi / wangwu / admin`，密码均为 `123456`
- 默认连接 `http://localhost:11434`（Ollama）与 `http://localhost:9200`（Elasticsearch），可用 `OLLAMA_BASE_URL` / `ELASTICSEARCH_URL` 覆盖；用 `KB_LLM_ENABLED=false` / `KB_ES_ENABLED=false` 可分别关闭。
- ES 索引 `kb_chunk` 首次启动自动创建，为空时自动从 H2 回填。当前嵌入仍是 256 维哈希向量，未启用 Ollama 嵌入接口；接入真实嵌入需调整维度并全量重建。详见交接文档 1.5、3.4、7 节。

### 2.1 一键自动部署（Windows，推荐）

前端会构建进后端 jar，部署后只需一个进程、一个端口：

```bat
deploy\deploy.bat deploy
```

脚本自动完成：检测 JDK 17 → 构建前端 → 打包带静态资源的后端 jar → 停止旧实例 → 启动新实例 → 健康检查 → 报告 Elasticsearch/Ollama 可用性。

```bat
deploy\deploy.bat status     :: 运行状态与依赖状态
deploy\deploy.bat restart    :: 不重新构建，直接重启
deploy\deploy.bat stop       :: 停止
deploy\deploy.bat logs       :: 查看最近日志
```

- 部署地址：`http://localhost:8090/`（页面与 `/api` 同端口）。
- 部署产物与日志：`deploy-runtime/kb-console.jar`、`deploy-runtime/logs/app.log`、`deploy-runtime/app.pid`。
- 默认沿用 `backend/data` 下的 H2 数据库与上传文件；可用 `-DataDir <目录>` 或环境变量 `KB_DATA_DIR` 指定。
- 自定义端口：`deploy\deploy.bat deploy -Port 8091`；跳过测试：`-SkipTests`；已有 jar 只重启：`deploy -SkipBuild`。

## 4. 术语约定

| 术语 | 英文 | 定义 |
| --- | --- | --- |
| 知识库 / 系列 | Series | 配置、权限、索引与检索的最小隔离单元。草稿中的“系列”与“知识库”视为同一实体，UI 统一文案为“知识库” |
| 可访问 | Accessible | 当前用户对知识库具备只读及以上权限（reader / editor / admin / owner） |
| 可维护 | Maintainable | 当前用户对知识库具备写权限（editor / admin / owner） |
| 解析引擎 | Parser | 将原始文件转成结构化文本的组件，含原生文本提取与 OCR |
| 解析策略 | Parse Strategy | 对某类文档采用“原生文本提取 / OCR 识别 / 自动判定” |
| 切片 | Chunk | 检索与嵌入的最小文本单元；父子切片包含父块与子块两层 |
| 索引策略 | Index Strategy | 知识库采用的索引方式，如向量索引、混合索引、（可选）图谱增强 |
| 召回 | Recall | 从索引中取回候选切片，默认混合检索 |
| 精排 | Rerank | 对召回结果做交叉编码器重排序 |
| 引用溯源 | Citation | 回答中标注来源文档、页码、段落或字符区间，可回跳原文 |
| 任务中心 | Task Center | 解析、切片、索引、重建、删除等异步任务的可观测入口 |

## 5. 关键设计决策

- **D1 知识库是隔离单元。** 配置、成员、目录、标签、文档、任务、索引全部挂在知识库下；“可访问/可维护”只是同一列表的两种权限视图。
- **D2 配置版本化。** 解析、切片、检索配置保存时生成不可变版本；异步任务绑定配置版本快照，运行中修改配置不影响在跑任务。
- **D3 全链路异步。** 上传接口只做校验、落存储、创建任务并入队；解析、切片、嵌入、写索引由任务中心驱动，可重试、可取消、可观测。
- **D4 检索默认混合 + 精排 + 溯源。** 向量与 BM25 双路召回，RRF 或加权融合后精排；切片保留页码、字符偏移、bbox 等定位信息。
- **D5 权限服务端强制。** 采用双层权限：全局 RBAC（用户、部门、角色权限）负责系统管理能力，知识库成员角色负责库内操作；前端导航与按钮仅是视图，接口用 `@RequirePermission` 与 `PermissionService` 在服务端强制校验。owner 不可移除，至少保留一名维护者。
- **D8 会话按账号隔离。** 每个用户可创建多个会话；用户 ID 只取自 Token 上下文，越权访问统一返回 404；生成时带入最近 6 轮上下文，检索仍只用当前问题。
- **D6 一期文档类型收敛。** 仅支持 PDF、DOCX/DOC、XLSX/XLS、Markdown；扫描件通过 PDF 或图片进入 OCR 链路（图片是否独立为一类格式待确认）。
- **D7 外部能力可插拔、可降级。** Elasticsearch 负责向量 + BM25 检索，Ollama 负责基于片段生成；任一依赖不可用时，检索回退本地 H2、生成回退为“只返回引用”，不阻断管理台主流程。

## 6. 一期范围

**范围内**

- 知识库列表（可访问 / 可维护）、卡片展示与检索
- 四步创建向导：基础信息 → 解析引擎 → 分块设置 → 高级设置
- 知识库信息编辑、配置维护、配置变更后的重建提示
- 成员与部门授权、成员增删改
- 目录树管理、标签管理
- 知识（文档）上传、列表、筛选、重传/停用/删除
- 任务中心：进度、失败原因、重试、取消
- 检索配置：混合检索、精排、引用溯源、TopK、相似度阈值
- 系统管理：用户管理（角色、部门、启停、重置密码）、部门树、角色与权限配置
- 问答中心：全局会话列表、多会话切换、重命名/删除、消息持久化、最近 6 轮上下文

**范围外（一期不做，接口预留）**

- 流式输出、查询改写、消息分页与会话归档（当前为同步 RAG：检索 + 最近 6 轮上下文 + 生成 + 引用）
- 真实嵌入模型接入（当前为 256 维哈希向量，Ollama 只用于生成）
- 文档在线预览/编辑器
- 知识图谱构建与 GraphRAG
- 文档版本管理与审批流
- 跨知识库联合检索
- 计费、配额与成本中心
